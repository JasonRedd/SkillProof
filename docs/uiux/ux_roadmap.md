# SkillProof UX Roadmap

## 1. The User Journey Map

### A. The Student Journey (The "Prover")
**Goal**: Demonstrate capability and earn verification.
1. **Onboarding**: Minimalist registration $\rightarrow$ Quick skill-interest selection.
2. **Discovery**: Browse "Challenges" $\rightarrow$ View difficulty, time limit, and potential skill gain.
3. **The Arena (Core Experience)**:
    - Enter challenge $\rightarrow$ Read requirements $\rightarrow$ Write code in the Integrated Editor.
    - **Iterative Loop**: Run Code $\rightarrow$ See Test Results $\rightarrow$ Refine Code.
    - **Final Submission**: Submit $\rightarrow$ Wait for Sandbox Verification $\rightarrow$ Get Final Score.
4. **Growth**: View "Skill DNA" $\rightarrow$ Identify weaknesses $\rightarrow$ Select new challenges to improve.

### B. The Recruiter Journey (The "Verifier")
**Goal**: Find proven talent without guessing.
1. **Search**: Search by skill (e.g., "Python") or minimum score (e.g., "Top 10%").
2. **Verification**: Click a profile $\rightarrow$ See "Skill DNA" $\rightarrow$ View evidence (specific challenges passed).
3. **Contact**: Direct link to student portfolio or LinkedIn.

## 2. Key Screen Specifications

### Screen 1: The Challenge Hub
- **Visuals**: Grid of "Challenge Cards."
- **Interaction**: Filter by category (AI, Web, Data) $\rightarrow$ Difficulty badge (Easy/Medium/Hard).
- **Action**: "Start Challenge" button.

### Screen 2: The Coding Arena (The "Heart")
- **Layout**: 70% Editor | 30% Sidebar.
- **Sidebar**: 
    - Challenge Description.
    - Timer (Count down).
    - "Run Tests" button.
    - Live result feed (? Test 1, ? Test 2).
- **Editor**: Dark theme, syntax highlighting, line numbers.

### Screen 3: The Skill DNA Profile
- **Visuals**: A large, interactive **Radar Chart** (Spider chart).
- **Metrics**: Logic, Efficiency, Readability, Consistency.
- **Achievements**: A gallery of "Verification Stamps" for completed hard challenges.

## 3. Interaction Principles
- **Instant Feedback**: The "Run" button should feel immediate.
- **Gamification**: Use progress bars and "level-up" animations when a skill score increases.
- **Clarity**: Errors must be descriptive (e.g., "Runtime Error: Division by Zero" instead of "Error 500").
